# 结构化绘图规格与审核稿

结构化绘图规格是冻结 Excel 与 Draw.io 之间的唯一中间层。先运行 `scripts/drawing_bridge.py` 从冻结工作簿编译初稿，用户审核稿由同一规格生成，不是第二套提示词事实源。编译脚本不推断未给出的内部操作、平衡结论或路线；这些待确认处必须在审核稿中露出。

```text
冻结 Excel
  → 读取模型过程与代表值物理流
  → 排除不属于物理流程图的分配负担与替代收益
  → 结构化绘图规格
  → 内容蓝图确认
  → 无色版式与内容复检
  → 视觉优化
  → Draw.io
```

## 字段来源

- `direct`：直接读取冻结 Excel。
- `derived`：依据唯一规则生成，例如外部输入端点。
- `confirmed`：用户确认，例如展开方式和是否显示。
- `layout`：布局产生，例如端口和间距。
- `qa`：检查产生，不能手工写成通过。

## 编译顺序

1. 读取项目、模型过程、模型流与公式、核算检查、问题与决策及绘图确认；把相关表格的内容指纹写入规格。
2. 验证冻结版本、模型过程 ID、流 ID、端点及目标研究的方法采用状态。
3. 只把已采用的代表值物理流编译为默认边；一条 Excel 流生成一条科学边记录。将替代候选保存为可选注释对象。
4. 以计算模型过程建立科学归属节点；按原文证据把需展开的内部操作逐个列入 `operation_coverage` 和 `operation_io`，登记目的及输入输出，而不是把整段仅写进黑箱说明。
5. 对每条科学流决定唯一展示位置：`display_edges` 定量箭头，或 `module_annotations` 模块总量。无独立量但有证据的单元间连接另登记 `topology_edges`；文本标签和箭头使用独立图元。旧规格中 `display_edges` 的无 `flow_id` 项应迁入 `topology_edges`，不能把它们计为第二条定量流。
6. 应用用户确认的展开、标签和显示决定；需要压缩卡片数量时创建不改变事实的 `visual_groups`。编译 `balances` 与恰好三张总输入、总输出、总能源 `summary_tables`；表格只引用既有外部流与核算记录。
7. 为每条展示箭头分配视觉角色、路由类别和默认固定端口，再进行无色坐标布局。
8. 完成用户审核后，用 `validate_drawing_spec.py <规格.json> --workbook <冻结Excel>` 逐条核对科学字段，再按 `figure-workflow.md` 依次执行内容复检和视觉优化；每关 QA 由实际检查产生。
9. 以规格中的实际展示图元 ID 作为 Draw.io 节点/边 ID；人工编辑图后同步复核映射，再运行结构和渲染检查。五关全部通过后冻结母版。任何相关 Excel 内容修改都使旧内容指纹失效，应重新编译，不能在 JSON 中手修科学数值。

## 审核稿必须回答

- 图中有哪些计算模型过程？
- 每个过程内部说明哪些设备操作，哪些得到确认并展开？
- 每条主线、支线、回流和边界流的来源、目标、代表值、单位和基准是什么？
- 是否存在来源分配负担被错误纳入？
- 副产品只是物理输出，还是已确认显示为后续替代候选？
- 哪些信息隐藏、合并或外置？
- 页面方向、车间顺序、主线位置、输入/输出层、端口、折弯预算和目标尺寸是什么？
- 哪些外部输入进行了视觉分组？分组内是否仍逐项显示名称、代表值和单位？
- 表格使用哪些列、精度和合计规则？
- 颜色、字体和装饰哪些已经确认，哪些仍保持开放？

不得从示例图、提示词、坐标、颜色或设备参数名补充科学事实。
