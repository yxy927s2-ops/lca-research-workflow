# 绘图功能：Draw.io 五关工作流

绘图功能把科学内容、版式和美化分开处理。每一关只解决一类问题；失败时返回指定上游，不在下游用缩字、加颜色或补注释掩盖问题。`../assets/绘图功能工作流_骨架版01.drawio` 仅概览关口和返工方向，具体检查与返回步骤以本文件为准。

## 入口

只有数据功能 Excel 已由用户确认并冻结，模型过程、采用候选、代表值和核算检查可追溯，且方法负担未混入物理流时才进入。绘图功能需用户另行启动，并沿用数据功能已交付的“数据支撑能力报告”；报告中已确认的定量层级不因绘图重新讨论。先读取 `drawing-spec.md`、`drawing-spec-fields.md`、`drawing-data-mapping.md`、`content-coverage-and-balance.md` 与 `expanded-operation-qa.md`；首例之后的同类课题再读实战模板 `case-drawing-spi-siegrist2026.md`（图面边界口径、回流取舍、分项—总计闭合、单位统一、干物质标注、总计表完整性、化学品三层校对）。

## 机器流水线（v15 起默认路径）

五关之外，v15 起默认先走两段机器流水线，AI 只处理两处判断（分类规则、注释措辞）；命令细节与设计 rationale 见 `machine-pipeline-design.md`。

1. **编译器 v2**：`scripts/build_figure_spec.py <冻结Excel> --template assets/drawing-spec-template.json --profile assets/display-profile-default.json --output <完整规格.json>`。科学内容经 `drawing_bridge` 取自冻结工作簿并记录内容指纹；展示层八节全自动补齐；脚本不得从提示词重新填数。显示分类规则在 `assets/display-profile-default.json`（以 SPI 案例 07 图为校准样本，项目内可覆盖）。
2. **渲染器**：`scripts/render_figure.py <完整规格.json> --style <样式手册.json> --output <图.drawio>`。两种模式：① `--layout <模板.json>` 版式模板模式（几何坐标全部取自验收案例图提取的模板；新案例先用 `scripts/extract_layout.py <案例图> --map <节点id映射.json> --output <模板.json>` 提取）；② 无模板时固定户型自动排版（三模块横排、操作竖列、输入左输出右，尺寸现算）。
3. **结构验证**：`scripts/validate_drawio_layout.py <图.drawio> --spec <完整规格.json> --workbook <冻结Excel> --final` 必须 PASS；再与案例基准图比对数值标签与总表（回归测试）。
4. **视觉验收（必经，与结构验收分开汇报）**：`scripts/export_png.py <图.drawio> --scale 1` 无头导出 PNG 并亲自分区放大全保真逐区查看（draw.io 桌面版自动探测，可用 DRAWIO_EXE 指定）。**必须用 scale 1**——scale 2 会触发 drawio 无头栅格化截断 bug，约一半内容丢失。逐区检查：走线正交无斜穿、连接线不穿越/不覆盖单元格、连接点落在框边缘、数值标签不贴线不压框、模块内布局紧凑无大片空白、整图居中、文字无溢出。结构 PASS 只证明映射与结构正确，不等于画对了。

历史教训：边拐点在案例图里是容器相对坐标，直接当绝对坐标会拉出跨图斜线；提取时必须只取 `<Array as="points">` 内的真拐点（忽略 sourcePoint/targetPoint）并换算为绝对坐标。

## 第一关：内容蓝图

目标：决定“必须画什么”，不决定颜色和精确坐标。

1. 运行 `scripts/drawing_bridge.py` 从冻结 Excel 编译机器检查用绘图规格初稿，保留一流一记录的科学边；编译警告不得由提示词自行填成事实。
2. 建立必要操作覆盖表，核对重复操作的次数与顺序。
3. 确定阶段、主线、支线、外部输入、输出、回流和未确认端点。
4. 平衡审查留在 Excel；除非用户明确要求，不在流程图放差异、未闭合或待核实标记。
5. 对每个必要单元操作登记简短目的、有证据的输入输出箭头；只有模块总量时在模块层显示数字，操作层只显示来源支持的定性连接，不把总量平均或猜配到设备。绿框内不重复“入/出”清单。
6. 确定流程区、图例区和下方总输入、总输出、总能源三张表的布局；图例位置依用户已确认样例而定，读取 `summary-table-design.md` 选择表格列结构。
7. 将以上内容整理为一份给用户看的结构化绘图说明/提示词，列出操作、每条显示流、图例、汇总表、未决项和拟借鉴的示例属性；请用户审核。该说明是绘图规格的人读版本，不是第二份科学数据源。

通过条件：拓扑、操作覆盖、图示数值、汇总内容和表格字段均已确定，且用户已认可绘图说明。未经认可不得开始正式初稿；科学结构改变时返回数据功能，不进入后续绘图。

## 第二关：无色版式

目标：只用中性色建立可读骨架。读取 `layout-routing.md`。

1. 先摆阶段容器、主轴和工艺节点，再放输入、输出和支线。
2. 建立真实表格行列，不用空格模拟列。
3. 分配流程、图例和汇总区域，按内容包络收缩容器。
4. 固定端口与路由，优先直线和短正交支线。
5. 使用最终目标字号，不通过“先缩小、以后再放大”换取空间。

通过条件：去掉颜色后仍能理解顺序、层级和流向；表格列对齐；没有溢出、遮挡、异常空白或必须穿框的连线。失败时只调整版式，不开始配色。

## 第三关：内容复检

目标：验证初稿是否忠实表达冻结数据。

逐项核对：

- 每个必要操作均有节点或经确认的显式聚合；
- 重复操作次数和编号顺序一致；
- 每条显示流的端点、数值、单位和计量基础正确；
- 流程图、图例和汇总表对同一流没有矛盾或重复计算；
- 水、总质量、蛋白和能源核算没有互相替代；
- 未确认的内部回用没有画成确定连线；
- 表格行数、合计和小数位与事实源一致。

实战增补（源自 Siegrist 2026 SPI 案例，详见 `case-drawing-spi-siegrist2026.md`）：

- **图面边界口径**：图上只画 LCA 边界交换；不进 LCI 的工艺投水、厂内循环不画入主体，仅在图注交代。内部回流全画或全不画，缺一项的"半套回流"必须返工；
- **分项—总计闭合**：每个模块能耗总计框等于其下各操作值之和；加不拢的差项（如作者公式整体乘系数的泵送）必须显式呈现（优先注进总计框自身，不新增图元、不在图底堆文字）；
- **单位统一**：同类量全图统一口径（水量统一 kg，m³ 只作换算注记）；改单位时图面框、总计表、图注三处同步；
- **干物质条件**：每张产品／副产物／废液卡标注干物质或含水条件，出处指向冻结清单字段或作者公式假设；
- **总计表完整性**：图面上每个有量流在总计表有对应行；补行时同步下移注释、加高页面；
- **化学品三层校对**：图上标签 ↔ 冻结清单流卡 ↔ 作者公式／数据表缓存值对齐，稀释倍数单独核验。

通过条件：内容覆盖率 100%，无错连、漏项、重复、单位冲突或平衡夸大。内容问题返回第一关；纯布局问题返回第二关。

## 第四关：视觉优化

目标：在不改变内容和拓扑的前提下建立统一视觉语言。

按顺序处理：

1. 字体层级与字重；
2. 网格、间距和留白；
3. 线宽、边框与箭头层级；
4. 颜色语义和对比度；
5. 图例分布、注释位置和可选装饰。

禁止在本关新增科学事实、改变流端点或通过缩字解决密度问题。示例图只提取用户指定或明确可辨认的视觉属性，不复制其科学内容。若存在多张示例，分别登记“借鉴版式、表格、色彩或线条”，避免混合冲突。

通过条件：颜色角色唯一、黑白状态仍可读、重点层级清楚、边框不争夺注意力、图例紧凑且覆盖全部视觉语义。

## 第五关：最终技术检查

目标：验证实际 `.drawio` 母版，而不是只检查计划。

1. 运行 `scripts/validate_drawing_spec.py <spec.json> --workbook <冻结Excel>`；它检查科学字段与结构，不证明图面无碰撞。
2. 运行 `scripts/validate_drawio_layout.py <drawio> --spec <spec.json> --workbook <冻结Excel> --final`。图元 ID 与端点必须与规格一致；缺少规格或 Excel 不得报告正式通过。若图中展开了子操作而验证器仍只接受汇总过程端点，按 `expanded-operation-qa.md` 增加可复现的父过程映射检查，分别报告科学层与展示层结果，不把误报当作无需检查的理由。
3. 临时渲染母版，在 100% 和预期 PPT/论文尺寸检查字体、表格、留白、颜色和线条；临时渲染图不放入交付目录。
4. 在 Draw.io 中确认文件可打开、对象可编辑、箭头仍连接正确。

任一硬性失败都返回对应关卡；不得通过后直接修改内容而不重新检查。人工调整 `.drawio` 后先更新或复核展示映射，再重跑两项检查；不得沿用过期规格，也不得忽略验证器失败。

## 交付

默认只交付通过第五关的 `.drawio`。JSON 规格、提示词、临时渲染图、PNG、SVG、PDF 和 PPT 只有用户明确索要时才提供。
