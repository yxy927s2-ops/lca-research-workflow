# v15 设计草案：从"冻结 Excel"到"案例那样的图"

> 写给不懂代码的人看的版本。把这套系统想象成**装修流水线**：Excel 是建材仓库，规格是施工图，编译器是搬建材上楼的，渲染器是按图施工的装修队，验证器是验收员。本文说明 v15 要新添的两台机器。

## 一、现在的流水线和差距

```
现在：  冻结Excel → [编译器v1：只搬科学内容] → 规格(一半空) → AI手工补八节 → AI手工搭图 → 验证器
目标：  冻结Excel → [编译器v2：搬全部能搬的] → 完整规格 → [渲染器：照图施工] → 图 → 验证器全机器核对
```

编译器 v1 实测：27 条流的数值、单位、端点全部正确。但规格里还有八节是空的，本轮靠 AI 手工填。下面逐节说这八节哪些能机器搬、哪些需要人判断。

## 二、第一块拼图：编译器 v2（搬数字的机器升级）

八节清单（"机器能搬吗"一栏是关键）：

| 空节 | 大白话是什么 | 数从哪来 | 机器能搬吗 |
|---|---|---|---|
| numeric_labels（22 条） | 图面上每个框里的数 | 流的"图示代表值"四舍五入 | ✅ 全自动。"画哪个框"绘图确认表已记了 |
| display_edges（14 条） | 哪些流真的画出来 | 绘图确认表的显示决定 | ✅ 全自动 |
| topology_edges（13 条） | 操作之间的连接箭头 | 绘图确认表的端点 | ✅ 全自动 |
| operation_coverage（13 条） | 操作覆盖核对 | 参数覆盖度矩阵 | ✅ 全自动 |
| balances（4 条） | 平衡声明（电/热加总等） | 核算检查表的 PASS 结果 | ✅ 全自动 |
| operation_io（13 条） | 每个操作"干什么、进什么、出什么" | 模型过程表的内部操作说明 | ✅ 机器出草稿，人审一遍措辞 |
| summary_tables（3 张） | 底部总输入/总输出/总能源表 | 流的分类汇总 | ⚠️ 数值机器算；"归到哪一类、排第几行"要一套分类规则——以本案为默认模板，人可改 |
| module_annotations（8 条） | 模块旁的小注释（如"泵送×1.15"） | 问题与决策表、图注 | ⚠️ 机器出草稿，人审定稿 |

**结论：八节里六节全自动、两节"机器出草稿人看一眼"。** v2 的工作量不大，因为数据源全在冻结 Excel 里，只是 v1 没去取。

## 三、第二块拼图：渲染器（照施工图施工的机器）

**它是什么**：输入"完整规格＋样式手册"，输出 `.drawio` 文件。没有智能，全是规则——但正因为没智能，它不会抄错数、不会忘了改单位。

**为什么规则写得出来**：通用自动排版是业界难题，但本 skill 的图是**固定户型**——永远是"三模块横排、模块内操作竖列、输入从左边进、输出从右边出、支线挂下方、底部三张表"。户型固定，施工规则就是一张能列完的表。真遇到奇葩户型（多条主线交叉），渲染器老实输出一份"这几处需要人工摆"的清单，不硬画。

**样式手册从哪来**：从案例 07 这张图里"提炼"，就是把这些视觉决定抽成常量存一个文件：颜色（模块框浅绿、能耗框浅橙、注释虚线灰）、字号层级（标题 22／正文 17／小字 15）、圆角、边距、表格行列宽高。07 图就是样板房，手册就是照着它抄下来的"装修标准"。

**版式规则草案**（照 07 的实际布局写成规则）：

1. 画布：单页横版，宽度按三模块总宽定，高度随内容自适应（本案 3040×1715）；
2. 模块：Ⅰ→Ⅱ→Ⅲ 从左到右，每模块一个大框，框内顶部写模块名；
3. 操作：模块内竖直排列，主线居中，支线从对应操作下方分叉；
4. 流：输入流从画布左侧垂直进入所属操作，输出流垂直向上/向右出模块（规格里已有 input_vertical/output_vertical 标记）；
5. 标签：每条显示流在箭头旁挂一个小标签框，值＋单位＋干物质条件；
6. 能耗：模块右下角放"电力/热量输入"总计框，分项值标在对应操作框内；
7. 底部：三张总表横排，下面一行图注、一行来源注；补行时自动下移注释、加高页面（本案踩过的坑写成规则）。

## 四、验收标准：回归测试（这轮实战白送的礼物）

v15 做完后用 SPI 案例全机器重跑一遍：编译器 v2 → 渲染器 → 两个验证器，必须 PASS；并且和现在的 07 图**逐框对比数值**——一模一样才算过。这个测试以后每次改 skill 都跑，谁改坏了立刻知道。

## 五、动手顺序

1. **编译器 v2**：小改，规则全在本文第二节（预计最快）；
2. **样式手册提取**：把 07 的样式常量抄成文件（机械活）；
3. **渲染器**：新写，按第三节规则（核心工作量在这）；
4. **回归测试**：跑通 SPI 案例，与 07 对比。
