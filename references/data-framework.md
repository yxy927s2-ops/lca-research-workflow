# 数据框架一页纲（v12 新增）

本文件统一定义数据功能的核心对象、数据层级、可采用标准与闸门状态，供 `excel-schema.md`、`source-and-candidates.md`、`data-inventory.md`、`data-capability-handoff.md` 共同引用；与其他 reference 冲突时以本文件与 SKILL.md 为准并回改出处。

## 目的三问

所有环节围绕研究者的三个问题组织交付：**① 文献里有什么数据？② 哪些能用、哪些应该用？③ 据此怎么建自己的课题模型？** 早期只做轻筛与角色分类（先明确重点，不逐篇平均用力）；细节审查在框架确认后按已批准范围展开。第三问的答案以"条件触发的建模接口"交付（见建模接口判定／闸门 C），本 skill 不计算 LCIA/LCC 结果。

## 数据路径（唯一主线）

`来源体系 → 文件/证据 → 候选数据 → 采用参数/流 → 公式/结果 → 模型过程 → 绘图对象`

每条采用值必须能沿此路径反查到证据位置；一个候选不必被采用；绘图对象只持有显示决定，不得持有第二套科学数值。

## 核心对象模型

| 对象 | 定义 | 关键状态／字段 |
| --- | --- | --- |
| 来源体系 | 一项研究的主文＋附件＋代码共享一个来源体系ID；文件数≠研究数 | 池角色：完整清单池／参数池（可兼任） |
| 候选 | 一行一个来源数值；原值永不被换算或排除覆盖 | 候选中／已排除／已采用；空白≠零 |
| 模型过程 | 科学数值的归属粒度（产品系统/模块/计算过程/单元操作） | 骨架须指回框架确认（闸门 A）的框架 |
| 模型参数 | 当前研究采用的参数，经 `采用候选ID` 指回候选或公式 | 分布归一类型＋图示代表值情景 |
| 模型流 | 一行一条采用交换（物理/环境/负担接口分开） | 直接报告／公式派生；内部/回流/聚合标记 |
| 公式节点 | 作者公式或代码版本及其输入参数 | 溯源完整／有缺口（缺口不臆填） |
| 问题 | 差异或疑点，登记影响对象 | 待决／已解决／阻断冻结 |
| 决策 | 用户对问题的处理决定及理由 | 关联问题ID；决定不修改也要记理由 |
| 覆盖项 | 一行一项“操作×参数/流需求” | 五级数据层级之一（见下） |
| 待补项 | 按操作索引的未解决缺口 | 开放／已补／用户接受（附决定） |
| 绘图对象 | 从冻结模型派生的显示决定 | 版式/标签/展开；不拥有科学数值 |

## LCI 数据支撑五级（统一词表）

覆盖度矩阵与数据支撑能力汇报必须使用同一套五级评定：

1. **操作级直接给出**——来源直接报告该单元操作的量；
2. **公式唯一拆出**——可由已采用公式从上级量唯一拆分；
3. **过程/模块总量**——只有聚合量，保留聚合边界，不按产量/价值/经验比例臆拆；
4. **仅拓扑/定性**——只有连接关系或定性描述，无量；
5. **缺失**——来源未提供且无公式可达。

总量不得硬拆到单元操作；设备名、图示小方块不自动等于可独立核算的操作。

## “可采用”的最低评估标准（候选→采用，四项齐全）

1. **证据定位**：来源文件＋页/表/代码位置可指回；
2. **原始语义完整**：原始值＋单位＋计量基准（湿/干基、纯度、参考流等）；
3. **可比性审查**：功能单位、系统边界、时空条件、方法口径逐项判断；不可比标`不可直接比较`，不强行排序或平均；
4. **方法口径记录**：来源 ALCA/CLCA 及是否已有分配/替代；目标研究的口径选择另记为用户决策。

四项不齐的候选保留在候选表，不进入采用模型。

## 闸门与流程状态

| 闸门 | 判定内容 | 否分支去向 |
| --- | --- | --- |
| C1 | 有完整生命周期清单？（完整≠参数齐全） | 报告所缺，用户补充/自行下载 |
| C2 | 完整清单池非空？ | 继续审查补充，不转纯建模 |
| 框架确认（闸门 A，含 A-1） | 框架参考获用户确认；否决则查池内候选 | 换候选；池竭报告等待，不自动建模 |
| C3 | 框架与原文功能单位/边界自洽？ | 冲突登记问题表，不受影响部分继续 |
| D1 | 该流参数是否涉及公式运算？ | 需计算→S3.5 递归溯源 |
| QC | 物料/水/能量平衡、覆盖、记录完整？ | 按缺口回对应环节；仍有问题即时报用户 |
| 冻结确认（闸门 B） | 用户确认清单、待补项与可冻结范围 | 按缺口返工重报；确认后冻结 |
| 建模接口判定（闸门 C） | 建模接口条件（见下） | 不具备→仅交付冻结清单 |

**建模接口判定（闸门 C）的满足条件（其一即可）**：① 采用值来自 ≥2 个来源体系；② 存在用户自有修正/补充决策；③ 方法口径（分配/替代政策）为课题自有选择。不具备时禁止输出建模接口，防止把单文献复现包装为目标研究模型。

**工作簿状态**：`draft`（默认）→ `frozen`（冻结确认／闸门 B 确认＋校验通过）。冻结需六要素齐备：完整清单池、框架确认（闸门 A）框架、逐流公式链、覆盖矩阵、QC问题汇报、冻结确认决定与冻结范围。解除冻结即返回数据功能。

## 命名与关联

- 所有对象持稳定 ID（来源体系ID/候选ID/参数ID/流ID/问题ID/覆盖ID/待补ID）；显示名（“归属单元＋来源—去向＋流类型”）仅供人读，不作关联键。
- 冻结后派生的任何产物（绘图规格、建模接口说明）必须能通过 ID 回溯冻结工作簿；内容指纹失配即重新编译。
