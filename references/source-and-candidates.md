# 来源、候选值与采用值

## 来源轻筛

收到资料后先建清单，不立即逐篇扒数。按一项研究的主文、补充资料、代码和导出文件登记 `来源体系ID`；文件数不是独立研究数。给每个文件记录角色、是否共享上游数据、原研究方法、产品/工艺覆盖、功能单位、边界和关键条件。S1.3 核验“是否有完整生命周期清单”只检验整链清单及其可追溯附件是否存在，不要求所有参数齐全。只在框架确认（闸门 A） 确认框架后按已批准范围详细取数。

S2.1 的框架候选说明可记录发表渠道和被引情况，但框架采用更要核对研究对象、系统边界、流程覆盖、公式/代码可复现性与本题适用性；文献权威性不替代模型证据。

S1.4 建立两个可重叠的角色池：有完整生命周期清单、能候选整链框架的来源进入`完整清单文献池`；能提供局部参数、公式、过程证据的来源进入`参数选取文献池`。一篇来源可同时在两池；框架确认（闸门 A） 选定框架后，未选完整清单来源自动并入参数池，同时保留完整清单候选角色和来源证据。完整清单池为空或框架候选耗尽时报告并等待文献补充/用户决定，不自动转入纯建模。多来源数据不自动合成为同一平均值或概率分布。

**多版本核验（v13 新增）**：同一下载渠道在不同时间可能挂出不同版本的附件或代码，文件名与下载日期都不构成版本证据。核验顺序：① 看文件内部标识——附件 README/标题是否与论文 DOI、正式题名一致（发现改题前工作版标题即判定为旧版）；② 做关键单元格内容指纹——与论文正文报告值、作者公开代码实际读取的 runtime 数据比对。发现多版本时全部登记到`数据来源`，指明本轮采用的权威版并记录判定依据；旧版数值不得进入候选，已误采的必须撤回重取。

**继承用户先前工作（v13 新增）**：用户在上一轮对话或交接文档中已完成审查的结论，可登记为 `SYS-UserPrior` 类来源体系。它可用于支撑建模接口判定（闸门 C）的“自有决策”条件、问题处理决定与工艺骨架继承，但其中任何数值要进入本工作簿，仍须指回原始文献证据并在`候选数据`建卡；不得仅因用户先前采用而直接成为采用值。

## 候选记录

`候选数据` 每行一项来源数值，保持稳定 `候选ID`，至少包含：所属参数/流对象、来源ID及证据位置、原始值/单位/基准、适用条件、分布原文、可依据的换算值/公式、可比性、采用状态和用户决策 ID。空白、未报告、不适用、已确认零分开表示。

`模型参数` 与 `模型流与公式` 只放当前研究采用的事实，并通过 `采用候选ID` 指回一个或多个候选。公式派生流可无直接候选，但须有公式、版本、输入参数及来源。候选修改不自动覆盖采用值；采用决定修改后，重算全部受影响结果及绘图标签。十篇文献的十个参数都可以保留，但 GSA 使用前还要检查条件可比性与来源相关性，不能把非独立或不同工艺条件的值默认为十次独立观测。来源内部引用的二手数据（二级引用）可保留为候选，但记录中须标注 `secondary_evidence` 并写明中间出处；采用前核对原始文献，GSA 使用前必须核原文；未核对前审查状态不得标 `PASS`。

## 基准与审查

先保存每篇文献自己的功能单位、参考流和条件，再记录到本研究功能单位的换算。单位换算、湿干基、产品纯度、产率、工艺边界、时空条件和 ALCA/CLCA 模型口径需逐项判断；同为每 kg 产品也不保证物理上可比。不可比时保留候选并标 `不可直接比较`，不强行排序。

所有拟采用值均需完成基础审查：证据定位、原始语义、单位与基准、流向/端点、公式及模型采用状态。主文、附件、代码冲突时做来源内部核对；独立来源且条件可比、用户同意时做跨来源核验。检查路线、实际执行结果和证据局限分别记录；未执行的核验不得标通过。

保持分配前物理流独立。来源 ALCA 分配因子、已分配负担，或 CLCA 替代/边际供应商做法都留作方法证据；研究目标方法由用户在入口确认，并在采用模型中选择。副产品实际质量不能被分配因子或替代收益改写。此 Skill 不计算 LCIA/LCC 结果。
