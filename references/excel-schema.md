# 数据功能 Excel v4.2：双文献池、覆盖矩阵与采用模型

从 `../assets/workbook-template.xlsx`（v4.2 工作簿模板）建立数据功能工作簿。模板十二表：保留来源、候选、采用模型及核算的原有事实分工，增设不持有科学数值的`参数覆盖度矩阵`和`待补参数清单`。不得把候选与采用模型混成一表，也不得建立第二套可手填的绘图数值。

| 表 | 用途与事实所有权 |
| --- | --- |
| `00_工作流总控` | S1–S4、框架确认／冻结确认（闸门 A/B）、QC 的九个数据功能控制行和绘图功能入口状态；不拥有科学数值 |
| `项目说明` | 目标研究的产品、功能单位、边界、方法、工艺路线和用户确认 |
| `数据来源` | 一行一文件，登记来源体系、角色、依赖、原研究方法与覆盖 |
| `候选数据` | 一行一个来源数值；原值、条件、分布、换算与可比性，不等于采用 |
| `模型过程` | 当前采用的计算过程、车间/阶段、顺序、聚合粒度和骨架依据 |
| `模型参数` | 当前采用的参数、分布与图示代表值；指回候选或公式证据 |
| `模型流与公式` | 当前采用的物理交换、环境交换、负担/替代接口及计算链 |
| `核算检查` | 基础审查、内部核对、跨来源核验、质量/水/能量与公式诊断；不反向驱动模型 |
| `问题与决策` | 差异、作用范围、候选处理与用户决定 |
| `绘图确认` | 从已确认模型派生显示决定；不拥有第二套科学数值 |
| `参数覆盖度矩阵` | 一行一项操作—参数/流需求；记录数据层级、证据、缺口及绘图可用层级，不重复数值 |
| `待补参数清单` | 按操作索引尚未解决的参数缺口，关联问题ID及用户决定；不是新数据来源 |

## 最小字段约定

- `项目说明`：目标 `建模模式` 由用户填 ALCA/CLCA；`工艺路线` 仅填框架确认（闸门 A）通过的`主文献锚定`，`整链主来源体系ID` 必须指向完整清单文献池的框架来源。没有候选时返回审查和补充，不填写自行建模。背景数据库和分配政策不可由来源自动代填。`数据功能状态=frozen` 必须有冻结确认（闸门 B）用户确认记录与冻结版本。
- `数据来源`：来源ID定位文件；`来源体系ID` 连接同一研究的主文、附件、代码；记录文件角色、独立性、上游依赖、原研究方法、工艺覆盖、原功能单位及详细提取状态。`文献池角色` 可同时填`完整清单文献池;参数选取文献池`，`完整清单证据` 指明整链清单所在附件/代码/表格，不把“参数齐全”当入池条件。
- `候选数据`：`候选ID`、`目标对象类型/ID`、`来源ID`、`证据位置`、`来源原名`、`原始值/单位/基准`、`适用条件`、`分布类型/参数`、`换算值/单位/研究基准/依据`、`可比性`、`采用状态`、`决策ID`、`备注`。一个模型对象可以对应多条候选。原值不因换算或排除而覆盖；空白不等于零。对于工艺拓扑证据可在 `模型过程.工艺骨架依据` 登记，不强迫伪造数值候选行。
- `模型过程`：`工艺骨架依据` 与 `骨架确认决策ID` 指回框架确认（闸门 A）通过的框架。计算过程为科学数值归属粒度；来源支持的内部单元操作在覆盖矩阵逐个登记，不能因没有操作级数值而被吞并为一个不可见黑箱。
- `模型参数`：新增 `采用候选ID`。多个可比候选仍保留在候选表；当前模型选值、分布和图示代表值只在本表保存一份。参数进入多个公式时，依赖关系逐一登记，不按一个参数一条流强行绑定。
- `模型流与公式`：一行一条采用模型交换。新增 `采用候选ID`、`数值生成方式`、`原始计量基准`、`采用计量基准`；原有 `CLCA采用状态` 改名为 `方法采用状态`，兼容 ALCA 和 CLCA。直接报告的流可没有公式，但要有来源、单位与基准；计算流须列公式和输入参数 ID。内外流、回流与聚合值分别标记，不能重复合计。
- `核算检查`：新增 `审查路线`、`实际验证结论`、`影响对象ID`。路线只是拟用方法，不能等同于执行成功。`问题与决策` 新增 `是否阻断冻结` 与确认日期；记录阻断作用域，而非一个问题冻结所有无关对象。
- `绘图确认`：`Edge` 行的 `对象ID` 与模型 `流ID` 相同；`代表值`、`单位` 两列由公式按 ID 联动模型流，不是可手填的第二套数值。用户只改显示/展开/标签决定。来源/目标端点若重复登记，必须与模型流一致；色彩、位置、端口与连接线几何留在绘图功能。
- `参数覆盖度矩阵`：`覆盖ID`、`模块/过程ID`、`操作ID`、`操作名称`、`所需参数/流ID`、`数据层级`、`证据来源ID`、`覆盖状态`、`关联问题ID`、`绘图可用层级`。数据层级使用直接操作量、公式唯一拆出、过程/模块总量、仅拓扑、缺失；总量不硬分给单元操作。
- `待补参数清单`：`待补ID`、`归属操作ID`、`参数/流ID`、`缺口原因`、`影响范围`、`关联问题ID`、`建议补充行动`、`用户决定`、`状态`。与`问题与决策`按 ID 关联，复查后仍有问题及时汇报，不以固定复查次数自动清除。

## 数据路径与冻结

`来源体系 → 文件/证据 → 候选数据 → 采用参数或流 → 公式/结果 → 模型过程 → 绘图对象`。每条采用值必须能沿路径反查；一个候选不必被采用。公式派生值走输入参数与公式证据链，不能为了填满 `采用候选ID` 伪造报告值。

模型事实的冻结不是 `核算检查=PASS` 的简单合计。还需确认完整清单池、框架确认（闸门 A）框架、逐流公式链、覆盖矩阵、QC 后问题汇报、冻结确认（闸门 B）决定及可冻结范围。审查记录在终端，不反向作为公式输入。数据功能交付 Excel 与数据能力汇报；绘图功能由 `scripts/drawing_bridge.py` 从冻结版本派生绘图说明的事实底稿与规格。修改相关 Excel 内容后旧规格的内容指纹失效，必须重新编译；单纯重存文件不构成科学内容变化。

## 与旧模板的兼容

原十表名称与核心列保留；v4.2 增加池角色、覆盖矩阵和待补清单。v4.1 的既有科学数值和联动公式不因流程更新而自动改变。旧工作簿可作为来源阅读；要走第十一版正式冻结时，迁移到 v4.2 工作副本并复核 ID、公式和新增关口，不能只改版本号。
