# 冻结数据到 Draw.io 对象的映射

本文件只决定“数据画成什么”，不决定颜色和装饰。读取冻结 Excel 的 `模型过程`、`模型参数`、`模型流与公式` 和 `绘图确认`，生成一套可逐项追溯的绘图对象。

## 1. 先区分过程、流和参数

- **过程**回答“在哪里发生”，编译为阶段容器、模型过程节点或经确认的内部操作节点。
- **流**回答“什么从哪里到哪里”，编译为有方向的边或边界输入/输出对象。
- **参数**回答“公式或操作采用什么条件”。只有参数本身也是物理流，或用户确认需要显示操作条件时，才进入主图。
- 公式、分布范围和不确定性参数默认留在 Excel；不得把公式变量自动画成物流。

## 2. 过程映射

| Excel 对象 | 图形对象 | 规则 |
| --- | --- | --- |
| 产品系统 | 页面或最外层容器 | 一个目标产品系统对应一个主画布 |
| 功能车间 | 阶段容器 | 按确认顺序从左到右排列，不把主支线当层级 |
| `model_process` | 主过程节点 | 一过程一稳定 `node_id` |
| `internal_operations` | 节点内说明 | 默认不产生新拓扑 |
| `expand_confirmed` 的内部操作 | 容器内子节点 | 必须有来源连接或用户确认的顺序与分支 |
| 外部系统边界 | `EXT_IN` 或 `EXT_OUT` 视觉对象 | 仅用于边界端点，不伪造成模型过程 |

展开后的子节点必须保留 `parent_process_id`。模型过程仍是核算归属，子节点只解释内部结构，除非来源本身在子节点层级给出独立流量。

## 3. 流映射

每条显示流必须保留：`flow_id`、`source_node_id`、`target_node_id`、`value_type`、`branch_role`、`representative_value`、`unit`、`basis`、`display_label` 和 `provenance`。科学端点仍是 Excel 的计算过程；当图中展开子操作时，另存实际展示端点及其父过程映射。

| 流类型与位置 | 默认图形 | 默认位置 |
| --- | --- | --- |
| 过程间主产品物料流 | 主线箭头 | 主过程行，水平连接 |
| 过程间支线物料流 | 支线箭头 | 主过程行下方或独立支线行 |
| 外部物料输入 | 输入卡片 + 指向消耗过程的边 | 目标过程上方 |
| 外部能源输入 | 有可信操作端点时用箭头；仅有过程/模块总量时用数值框 | 目标过程上方，不把总量摊到无证据的设备 |
| 主产品输出 | 产品节点 | 最右侧主线终点 |
| 副产品物理输出 | 输出卡片或副产品节点 | 产生过程下方或右下方 |
| 环境交换 | 排放/废水输出卡片 | 产生过程下方，使用独立视觉角色 |
| 回流 | 回流边 | 从阶段容器外侧绕行，不穿越主节点 |
| `allocated_burden` | 不作为物理流边绘制 | ALCA/CLCA 均须与分配前物质量分开 |
| `substitution_candidate` | 可选接口或注释 | 不作为物理流边，且不预先扣减 |

## 4. 外部输入的视觉分组

科学数据保持一流一记录。只有同时满足以下条件时，多个输入才可放入一个视觉卡片：

1. 目标过程相同；
2. 流向相同；
3. 不会混淆物料、能源与环境交换；
4. 卡片逐项显示流名称、代表值和单位；
5. 规格保存 `visual_group_id` 和完整 `member_flow_ids`。

视觉分组只减少卡片数量，不合并数值、不改变端点、不生成新的科学流。一个卡片跨越多个目标过程时必须拆开。

## 5. 参数显示规则

- `physical_material`、`physical_energy`：按流显示代表值和单位。
- pH、温度、停留时间、浓度等操作参数：只有用户确认其对理解流程重要时，作为节点内的 `operating_condition` 显示。
- 分布类型、上下限、公式和参数 ID：保留在 Excel 与审核稿，不进入常规主图。
- 图中值使用显示精度，规格同时保留未经舍入的 `source_value`。显示值不得参与重新计算。
- 标签默认采用“流名称 + 代表值 + 单位”；计量基础无法从标题或图注明确时，附加简短 basis。

## 6. 信息密度降级顺序

图面过密时按以下顺序处理，不得直接删除科学流：

1. 缩短显示标签，但保留完整名称映射；
2. 将公式、分布和来源移出主图；
3. 对同一目标的同类外部输入建立视觉分组；
4. 将次要操作条件移到图注或编号说明；
5. 将大型流程拆为总览图和局部详图。

任何隐藏或外置都写入 `display_decision`，并保留原始 `flow_id` 或 `parameter_id`。

## 7. 映射审计

生成 Draw.io 前逐项核对：

- 每个 `include=true` 的过程至少有一个图形对象；
- 每个 `include=true` 的流恰好对应一个科学记录；可表现为一条有证据端点的定量边，或一个无法细分到操作的模块级数值框，不能两者重复计数；
- 视觉分组的成员集合与 Excel 流集合一致；
- 图示代表值、单位和 basis 与冻结 Excel 一致；
- 参数没有被误画成物料流；
- 分配负担和替代收益没有冒充物理流进入图；
- 被隐藏或外置的对象有明确决定记录。
