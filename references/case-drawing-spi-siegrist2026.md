# 绘图实战模板：Siegrist 2026 SPI 前景清单图（图版 07）

本案是绘图功能首例端到端实战（数据功能 v4.2 冻结 → 单页流程化清单图）。本文把判决一般化为可复用规则，每条附本案落点。同类课题绘图时先读本文，再回到 `figure-workflow.md` 走五关。

## 案件锚点

- 框架文献：Siegrist et al. (2026), Sustainable Production and Consumption 62, 127–138（SPI 价值链，ALCA 口径的参数化 LCA 平台；本课题为 CLCA，范式不同——文献的 economic allocation 做法登记为对照留档，替代/系统扩展接口在 CLCA 层单独定义）。
- 功能单位：1 kg SPI；三模块（Ⅰ 清理破碎脱皮／Ⅱ 调质压片脱脂／Ⅲ 碱提等电点沉淀提取）。
- 数据交付：`SPI_CLCA前景清单_v4.2_frozen.xlsx`；图交付：`SPI基于流程的前景清单07.drawio`；规格：`drawing_spec_final.json`。
- 图面结构：上方三模块流程区（单元操作＋流程化输入输出＋模块能耗总计框），下方总输入／总输出／总能源三张表＋来源注＋图注。

## 判决一：图面只画 LCA 边界交换

**规则**：图上只画建模关心的外部输入／输出；工艺投水、厂内循环、设备自带水等"不进 LCI"的量一律撤出图面主体，最多在图注说明口径。理由：审图人按图面加总，画了就要闭合；作者口径对不上又闭不拢的量，呈现即招质疑。

**本案落点**：作者 tap_water 公式值 16.98 kg 为建模外部取水（锁定进 LCI），图上唯一水输入框；步骤加水 25.852 kg（浸提 19.852＋洗涤 6.0）含厂内循环，不画入图、不进 LCI，仅图注一句交代。作者 Overview 16.5036 与 Formulas 16.98 两口径的差异（0.4764＝自带水符号重复计）登记在冻结清单 Q04，不在图面呈现。

## 判决二：内部回流的"全有或全无"

**规则**：内部回用流（回流工艺水、循环水）要么全部画出并配平，要么整条不画；只画一条会让审图人质疑"其他单元的回流去哪了"。画不画由用户裁决，默认建议不画（对 LCA 建模无影响时）。

**本案落点**：用户裁决"回流全部不要"，图上零回流箭头；残余不平衡（进 17.49 ↔ 出 16.74，差 0.74＝酸碱溶液水 0.268＋符号重复 0.476）如实留在图注与冻结清单，不用假箭头补齐。

## 判决三：分项必须能加总成总计

**规则**：模块能耗总计框的值必须等于其下各单元操作值之和；加不拢的差项是公式结构的一部分（如泵送附加系数），必须显式呈现——优先注进总计框自身（加一行小字），不新增图元、不在图底堆文字。

**本案落点**：模块Ⅲ电力 0.0630 kWh ＝ 五操作 0.05478 ＋ 泵送 0.00822。作者公式结构为（离心＋压榨）×(1＋pumping 中值 15%)，裁决在"电力输入"框内加第三行"含泵送 0.0082（×1.15）"。热量天然闭合（3.0438＋0.7545＋23.7025＝27.5008 MJ），不加注记。曾试过的独立小框方案被用户否决——图面新增元素要克制。

## 判决四：单位统一为质量口径

**规则**：图中水量统一 kg；来源以 m³／L 列示的量，图上改 kg 并在图注给出换算（原文 m³ 值＝kg 值）。改单位时**图面框、总计表、图注三处同步改**，只改一处必然留下口径冲突。

**本案落点**：喷雾蒸发水由 0.004938 m³ 改 4.9375 kg（0.95/0.16−1）；输出总表第 7 行同步改（曾是"原文列示 m³"遗留）；图注加"图中水量除注明外均为 kg"。复核时正是发现总表与框不一致才补齐。

## 判决五：产品／副产物卡逐卡标注干物质条件并给出处

**规则**：每张产品、副产物、废液卡除质量外，标注干物质或含水条件（干基%／含水%），来源指向冻结清单字段或作者公式假设项。没有干度条件的卡，LCA 建模阶段无法对接背景数据。

**本案落点**：SPI 1.0000 kg 干物质 95%（作者 dm_output）；白豆片 1.9852 kg 干物质 88%（SPI!H29）；提取后豆片 0.5449 kg 含水约 10%（作者 tap_water 公式 SPI_spent_flakes×0.1 假设）；来源注卡集中列明三处出处。

## 判决六：总计表与图面一一对应且行数完整

**规则**：下方三张总计表是图面的会计视图：图面上出现的每个有量流，总表里必须有对应行（除非用户确认省略）；行值、单位、小数位与图面框一致。补行时同步下移图注／来源注、加高页面。

**本案落点**：复核发现闪蒸水蒸气 0.2096 kg 有图面无表行——补总输出表第 9 行，图注与来源注下移 43 px、pageHeight 1670→1715。能源合计行交叉验证：电 0.0164＋0.0788＋0.0630＝0.1582 kWh；热 1.8897＋27.5008＝29.3906 MJ。

## 判决七：化学品三层校对链条

**规则**：化学品流（酸碱、溶剂等）按"图上标签 ↔ 冻结清单流卡 ↔ 作者公式／数据表缓存值"三层对齐，稀释倍数单独核验（原液浓度→使用浓度的换算系数）。

**本案落点**：NaOH 10% 0.1241 L ＝ WF 1.9852×0.00125×10×5（50%→10% 乘 5）；HCl 10% 0.1737 L ＝ ×0.0029167×10×3（30%→10% 乘 3）；与作者 SPI 表 I51/I52 缓存值逐位一致。酸溶液水约 0.268 L 与水量边界残差互相印证（判决一的 0.74 拆解）。

## 判决八：能耗拆分须回溯作者公式结构，不只对总数

**规则**：把模块能耗拆到单元操作时，先还原作者公式的组合结构（哪些项相加、哪个系数乘在外面），再决定每项的画法；拆分值与作者数据表中按操作列出的值（如有）逐位比对。

**本案落点**：作者 SPI 表 N 列按操作给出 kJ 中值（浸泡 3043.83、离心 72.37/4.52/67.89/49.63、压榨 2.80、闪蒸 754.53、喷雾 23702.47、泵送 29.58），图上各操作值由此换算（÷3600 得 kWh、÷1000 得 MJ），逐位吻合；泵送不在 N 列的任一操作里、是整体乘出来的，这正是判决三要求的显式呈现。

## 工具纪律（本案血泪）

1. **双副本指纹比对**：工作区副本与用户手头的 `.drawio` 会分叉（用户随时手调框尺寸）。任何"改完同步到对方"之前必须比对两边 MD5；不一致时以**用户侧为基准**拉入工作区再改。本案教训：同步前漏比对，覆盖掉了用户手调的白豆片框。
2. **改前备份**：改用户侧文件前先把其当前版本备份到工作区（`…_desktop_backupN.drawio`）。
3. **复制用 Python shutil**，不用 shell cp 处理中文路径（引号转义出过错误）。
4. **长脚本写成 .py 文件再跑**，不用 heredoc／内联 -c 写多行修改（被截断过一次）。
5. **验证双跑**：`validate_drawing_spec.py`（规格）与 `validate_drawio_layout.py --final`（母版）都 PASS 才算过；工作簿未动时不跑工作簿校验。
6. **图注措辞与图面同步**：呈现方案改变后（如泵送从"单列小框"改为"注于框内"），图注里的旧措辞必须同步改，否则出现指向不存在元素的注记。
